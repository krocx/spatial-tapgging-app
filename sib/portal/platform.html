Where Applied can be ahead

  • Own the backbone, not a vendor's app. Every product here runs on SIB — anchors, world maps, validation and usage data are Applied's, deployable on-prem inside the fab network.
  • Validate, don't just display. Most AR tools show steps. Ours checks them spatially, records the verdict, and never blocks the line — a failed check can be overridden, but it is logged.
  • Pluggable intelligence. Validation runs on our engine today and can call any model — internal or third-party — through an API, so we ride every improvement in vision AI without rebuilding the platform.
  • One platform, many BUs. OMS, on-the-job training, EHS audits and lockout/tagout share the same authoring, access control and reporting — each BU gets a product, Applied keeps one system.
  • Authoring measured in minutes. Guides come from Excel, JSON or MES exports, or from the visual Procedure Designer — and any guide can be edited round-trip.

📋 AR Work Instructions

PILOT-READYAR OMS · AR OJT (on-the-job training)

What it is

Procedures shown in AR on the actual tool — each step pinned where the work is, with 3D ghosts of the correct result.

Why we built it

Procedure knowledge lives in people and PDFs. We wanted it to live on the equipment.

How it helps you

  • Faster ramp — the guide teaches while they work (AR OJT)
  • Fewer skipped steps; critical ones validated on the spot
  • Audit-ready record per Production #

Where it stands

Live on cloud and in-house servers. Best first use: a procedure you already have in Excel.

🎯 Spatial Validation

PILOT-READYAR-guided · own models or third-party via API

What it is

Confirms hands-on work was done right: the technician stands where the author stood; the platform compares the live view with "correct", from several angles.

Why we built it

Vision systems validate parts on a line — nothing validated a technician's work at a tool.

How it helps you

  • Catch the missing guard before the tool restarts
  • Objective verdict per step, on record
  • Pluggable engine — ours today, any model via API

Where it stands

Multi-angle training and guided capture live; scoring tuned with field tests.

🛰 SIB — Spatial Intelligence Backbone

IN PRODUCTION USEThe engine every product runs on

What it is

The foundation: QR anchors tie content to equipment, world maps let any iPad re-find it, plus validation, telemetry, access control and usage records — one server, on-prem or cloud.

Why we built it

Every AR product needs the same 80%. Built once, each new product is a thin layer — GembaWalks and iLOTO took weeks.

How it helps you

  • Data can stay inside the fab network
  • One user list and role model across products
  • Authoring from Excel / JSON / MES or the visual designer

Where it stands

Running continuously; hardened for pilots. Spatial data formats patent-pending.
